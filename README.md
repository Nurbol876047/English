## Word Order — Hand Control

Упражнение на построение порядка слов: слова лежат в 3D-«лотке», ячейки предложения — сверху.
Пользователь **сжимает большой и указательный палец** (pinch) рядом со словом, переносит его в ячейку
и разжимает. Правильная ячейка — вспышка частиц и звук, неправильная — плашка трясётся и возвращается в лоток.
Мышь и тач работают всегда — как fallback и просто параллельно с рукой.

### Архитектура

```

  HandCursor3D.tsx        3D-курсор указательного пальца, кольцо сжимается по pinchStrength
```

### Как рука попадает в сцену

1. MediaPipe отдаёт 21 landmark в нормализованных координатах кадра (0..1). Берём кончик указательного пальца (`landmark[8]`).
2. Кадр фронтальной камеры зеркальный → `x' = 1 − x`. Переводим в NDC: `ndcX = x'·2 − 1`, `ndcY = 1 − y·2`.
3. `Raycaster.setFromCamera(ndc, camera)` и пересечение луча с плоскостью взаимодействия `z = 0`
   (`ray.intersectPlane`) — все плашки и ячейки лежат на ней.
4. Результат сглаживается EMA (α ≈ 0.35), чтобы убрать дрожание трекинга.

Мышь/тач идут тем же путём: `clientX/Y` → NDC → та же плоскость. Захват плашки мышью — через
pointer-события R3F прямо на mesh (`onPointerDown` в `WordTile3D`).

### Детекция щипка

Расстояние «большой палец – указательный» (`landmark[4]`–`landmark[8]`) делится на размер ладони
(`landmark[0]`–`landmark[9]`, запястье → основание среднего пальца). Получается безразмерный
коэффициент, одинаковый на любом расстоянии от камеры: ~0.8–1.2 для раскрытой руки, ~0.15–0.3 для
сомкнутых пальцев. Порог с гистерезисом: захват при `< 0.35`, отпускание при `> 0.5` — иначе на
границе порога захват «дребезжит».

### Логика упражнения

- Случайное предложение → слова перемешиваются (гарантированно не в исходном порядке).
- Проверка выполняется в момент броска: `sentence.words[slotIndex] === tile.word` (сравнение по тексту,
  поэтому одинаковые слова в предложении взаимозаменяемы). Правильная плашка фиксируется в ячейке.
- **Streak** растёт за каждое предложение, собранное без единой ошибки; любая ошибка сбрасывает его.
- **Mastered X / Y** — темы, по которым набрано 3 правильных предложения подряд (`MASTERY_THRESHOLD`).
- `onExerciseComplete({ sentenceId, correct, timeSpentMs, attemptCount })` вызывается после каждого
  собранного предложения — точка интеграции с прогрессом платформы (см. `page.tsx`).

### Производительность

- Детекция руки крутится в собственном `requestAnimationFrame`-цикле, не связанном с `useFrame`,
  и ограничена ~22 fps; кадр не отправляется, пока предыдущий не обработан.
- MediaPipe грузится лениво (`import()` после старта камеры), WASM и модель — с jsDelivr CDN.
- Bloom — селективный (`<Selection>` / `<Select>`): светятся только захваченная плашка, ошибочная
  плашка и активные ячейки, а не вся сцена. `multisampling={0}`, dpr ≤ 1.75.
- Landmark'и не проходят через React-state: хук отдаёт `frameRef` + `subscribe()`, сцена и оверлей
  читают их из своих циклов.

### Известные ограничения

- **Браузеры.** MediaPipe Hands (WASM + WebGL) стабильно работает в Chrome / Edge / Firefox на десктопе.
  Safari iOS ограничивает `getUserMedia` и WebGL в WASM — на мобильных модуль автоматически
  переключается в 2D-режим без камеры (порог: ширина < 768px или мобильный UA).
- **Освещение.** Трекинг требует равномерного света на руке и контрастного фона; в тени/контровом
  свете рука теряется (статус «Покажите руку в кадр»).
- **Одна рука.** `maxNumHands: 1` — используется первая распознанная рука.
- **Интернет.** WASM/модель MediaPipe и шрифт для `<Text>` (troika) подгружаются с CDN.
  Для офлайн-развёртывания скопируйте файлы из `node_modules/@mediapipe/hands` в `public/` и
  поменяйте `MP_CDN` в `useMediaPipeHands.ts`.
- **Разрешение камеры.** Если пользователь отклонил доступ — статус «Камера недоступна», управление
  мышью/тачем остаётся полностью рабочим.
- **@mediapipe/camera_utils** не используется: свой rAF-цикл с ограничением fps проще и даёт контроль
  над нагрузкой.

## Sort the Words — Hand Control

Слова по одному вылетают из глубины сцены и парят в центре; три корзины-категории стоят внизу
(x = −3.6 / 0 / 3.6) — ровно над тремя потоками видеофона. Пользователь отправляет слово в корзину
одним из двух жестов, проверка мгновенная: верно — слово по дуге Безье улетает в корзину, вспышка
частиц цветом корзины и звук; ошибка — красный shake и второй шанс (в hard-mode слово улетает
в неверную корзину и засчитывается ошибка).

### Архитектура

```
  SortWordsScene.tsx      <Canvas>: камера [0, 1.5, 9] с наклоном вниз, свет, Selection + SelectiveBloom
  Basket3D.tsx            корзина: открытый цилиндр + светящийся ободок (EdgesGeometry), подсветка
                          при наведении/прицеле, импульс при попадании; клик = сортировка мышью
  FlyingWord3D.tsx        слово: incoming → waiting → grabbed → flying (Безье) / rejected (shake)
```

### Режимы управления

**Pinch.** Щипок рядом с парящим словом (радиус 1.0) — захват; слово следует за кончиком
указательного пальца с лагом; разжатие в зоне корзин (y < −0.8, |x − bx| < 1.6) — сортировка,
иначе слово возвращается в центр.

**Swipe.** Берётся центр ладони (среднее landmark'ов 0, 5, 9, 13, 17 — стабильнее пальца при
быстром движении). `SwipeDetector` держит кольцевой буфер из 12 позиций (~0.5 с при 22 fps) и на
каждом кадре считает Δ к позиции 6 кадров назад: скорость `v = |Δ| / Δt`, угол `atan2`.
Свайп засчитан, если `v > 6` ед/с, ладонь открыта на ≥ 70 % кадров окна и угол попадает в сектор:
влево 150–210° → корзина 0, вверх 60–120° → корзина 1, вправо ±30° → корзина 2. Диагонали и
«вниз» игнорируются. Гистерезис (`v < 2` для перезарядки) и cooldown 600 мс защищают от
повторного срабатывания и «возврата руки». При `v > 2.5` корзина по направлению подсвечивается
как прицел. Ладонь открыта = ≥ 3 из 4 пальцев вытянуты (кончик дальше от запястья, чем PIP).

**Мышь / тач** работают всегда: drag плашки (pinch-режим), быстрое движение с зажатой кнопкой
(swipe-режим, берутся coalesced-события) и просто клик по корзине. Пока кнопка зажата, кадры
руки не двигают курсор.

### Очки и прогресс

+10 за верное, +5 если решение быстрее 2 с, −5 за ошибку (не ниже 0). Streak — верные подряд.
Раунд 60 с; пройден при ≥ 80 % верных от размера набора; набор освоен после 2 пройденных раундов
подряд. `onExerciseComplete({ setId, total, correct, wrong, score, timeSpentMs, controlMode, passed })`
вызывается один раз по завершении.

### Как добавить набор

В `src/lib/sort-words/wordSets.ts` добавить объект `WordSet`: ровно 3 категории (цвета `sky` /
`violet` / `emerald` соответствуют корзинам слева направо) и ≥ 12 слов. Слово должно однозначно
принадлежать одной категории — омонимы вроде «run», «light», «work» не включать.

### Известные ограничения

- Свайп чувствителен к fps камеры и освещению: при < 15 fps окно детектора растягивается и
  скорость занижается — на слабом CPU снизить `modelComplexity` до 0 в `useMediaPipeHands.ts`.
- Пороги `DEFAULT_SWIPE_CONFIG` калибровались на синтетике 22 fps; в dev-сборке текущая скорость
  и угол выводятся в HUD (`v … · ∠ …`) — по ним удобно подстраивать под конкретную камеру.
- Взмах «вниз» не используется намеренно: рука в кадре обычно внизу и уходит из поля зрения.
- Остальные ограничения (браузеры, освещение, CDN) — как у Word Order.
